Rename Invoice.notes to Invoice.title and make it required

The "Notes (optional)" field on the invoice form was never really an
optional note - it's the invoice's title (what shows in the PDF's
"Invoice Title" column, in emails, everywhere), and every historical
invoice already has one. Leaving it labeled and typed as an optional
note was misleading and let new invoices get created without a title.

- Schema: Invoice.notes -> Invoice.title, now NOT NULL (migration
  renames the column and tightens the constraint - a plain rename, no
  data loss; verified beforehand that all 902 existing rows already had
  a non-empty value).
- CreateInvoiceDto.title is now required; UpdateInvoiceDto.title stays
  optional (partial updates) but rejects an empty string when given.
- invoices.service.ts, invoice-pdf.ts (both the server and browser PDF
  renderers), and the search filter all follow the rename.
- InvoiceNew.tsx: relabeled "Notes (optional)" -> "Invoice title",
  required, switched from a textarea to a single-line input (every
  existing value is a one-line title, not a paragraph).
- InvoiceDetail.tsx: shows it as an always-present "Title" row instead
  of a conditionally-rendered paragraph.
- quotes.service.ts: converting an approved quote to an invoice now
  falls back to the job/property/account name when the quote itself
  has no notes, since the invoice it creates can no longer have a null
  title.
- import-excel.ts: recognizes an optional Title/Notes/Description
  column, falling back to "{account} - Invoice {number}" so the
  importer still works against sheets that don't have one.
- seed-demo-data.ts: derives a title from each demo invoice's line
  items.

Unrelated to Account.notes, Payment.notes, and Quote.notes - those stay
untouched freeform note fields.
